# Claude Chat & Cowork — Recap & Prompt Playbook

Web presentation สำหรับการอบรม Claude ให้ผู้เข้าอบรม AP Thailand 35 คน (21 สิงหาคม 2026)
พูดบนเวที 10–15 นาที แล้วแยกลง workshop

Design ตาม pattern ของ deck องค์กร AP (`references/Snowflake-CoWork-Presentation.pptx`) — ฟอนต์ AP,
สีแดง `#921C1E`, canvas 20 × 11.25 นิ้ว, kicker + title + footer เหมือนต้นฉบับ

## เปิดใช้งาน

**เว็บที่เผยแพร่แล้ว → https://suphakornp.github.io/ap-claude-training-deck/**
ส่งลิงก์นี้ให้ผู้เข้าอบรมได้เลย เปิดจากคอมพิวเตอร์หรือมือถือก็ได้ ไม่ต้องติดตั้งอะไร

เปิดในเครื่องเอง — เปิด `index.html` ได้โดยตรง หรือรัน local server:

```bash
python3 -m http.server 4173
```

แล้วเปิด `http://localhost:4173`

## การควบคุมบนเวที

| ปุ่ม | ทำอะไร |
| --- | --- |
| `←` `→` `Space` `PageUp` `PageDown` | เปลี่ยนสไลด์ |
| `+` / `−` | **ขยาย / ลดขนาดตัวอักษร** — 6 ระดับ 90% / 100% / 110% / 120% / 135% / 150% |
| `0` | รีเซ็ตขนาดตัวอักษรเป็น 100% |
| `F` | **เต็มจอ = โหมดนำเสนอ** |
| `P` | เปิด prompt template ของสายงานในสไลด์ปัจจุบัน |
| `G` | เปิดคู่มือพร้อมใช้ 4 ขั้นของสายงานในสไลด์ปัจจุบัน |
| `L` | เปิดคลัง prompt รวมทุกสายงาน (ค้นหา + กรองได้) |
| `O` | สารบัญ |
| `Home` / `End` | สไลด์แรก / สุดท้าย |
| `Esc` | ปิดหน้าต่างที่เปิดอยู่ / ออกจากเต็มจอ |

### ขึ้นจอใหญ่ — ทำสองอย่างนี้

1. **กด `F` เข้าโหมดนำเสนอ** แถบเครื่องมือจะลอยและซ่อนตัวเอง สไลด์กินพื้นที่จอ 99%
   ตัวอักษรใหญ่ขึ้นจากตอนมีแถบประมาณ 16% โดยไม่ต้องแตะปุ่มขยายเลย
   ขยับเมาส์เมื่อไหร่แถบเครื่องมือจะโผล่มา 2.6 วินาทีแล้วซ่อนอีกครั้ง
2. **ถ้ายังต้องการใหญ่กว่านั้น กด `+`** ระยะห่างและระยะบรรทัดจะหดให้อัตโนมัติเพื่อรักษากรอบไว้

ขนาดตัวอักษรถูกจำไว้ใน browser — ตั้งค่าก่อนขึ้นเวทีได้ เปิดใหม่จะได้ค่าเดิม

ตารางความพอดีของกรอบตามระดับตัวอักษร (วัดจริงทั้ง 18 สไลด์):

| ระดับ | ผล |
| --- | --- |
| 90% / 100% | พอดีกรอบทุกสไลด์ — **100% คือค่าที่ออกแบบไว้ ใช้ตอนพูดจริง** |
| 110% | พอดีเกือบทุกสไลด์ (เหลือ 2 สไลด์ที่ล้นไม่ถึงหนึ่งบรรทัด) |
| 120% ขึ้นไป | สไลด์ที่เนื้อหาแน่นจะเลื่อนอ่านในกรอบ เหมาะกับอ่านบนโน้ตบุ๊ก ไม่เหมาะตอนพูด |

กรอบสไลด์พอดีจอเสมอ ไม่ว่าตั้งขนาดตัวอักษรเท่าไหร่ — ส่วนที่ล้นจะเลื่อนอยู่ในพื้นที่เนื้อหา

### มือถือ

แนวนอน — ดูสไลด์ได้ ปัดซ้ายขวาเพื่อเปลี่ยนสไลด์
แนวตั้ง — สไลด์ 16:9 เล็กเกินอ่าน หน้าจอจะเปลี่ยนเป็นทางเข้า **คลัง Prompt** และ **สารบัญ** แทน
ซึ่งเป็นสองอย่างที่ผู้เข้าอบรมต้องใช้จริงตอน workshop (คัดลอก prompt จากมือถือได้เลย)

ทุกสไลด์มี hash ของตัวเอง เช่น `#construction` `#finance` `#prompt-templates` ส่งลิงก์ตรงไปสไลด์นั้นได้

## เนื้อหา

18 สไลด์ แบ่ง 5 ช่วง

| # | ช่วง | สไลด์ |
| --- | --- | --- |
| 1–2 | เปิดเรื่อง | ปก, Agenda |
| 3–5 | รู้จัก Claude | Claude คืออะไร/ใช้ทำอะไร, **Chat เพื่อนคู่คิด · Cowork ลงมือทำ**, 6 จุดเด่น |
| 6–7 | เขียน prompt | สูตร prompt 5 ส่วน, prompt ที่ยังใช้ไม่ได้ vs ใช้ได้จริง |
| 8–14 | Use case แยกสายงาน | divider + 6 สไลด์สายงาน |
| 15–18 | สิ่งที่ส่งมอบ + ลงมือต่อ | Prompt template, คู่มือพร้อมใช้, กฎการใช้ข้อมูล, 7 วันแรก + workshop |

เดคนี้พูดเรื่อง Claude อย่างเดียว — ไม่เอ่ยชื่อเครื่องมือของค่ายอื่นบนสไลด์เลย (ตรวจแล้วทั้ง 18 สไลด์)
สไลด์ 4 เทียบสองหน้าของ Claude เอง คือ Chat กับ Cowork ไม่ใช่การเทียบกับเครื่องมืออื่น
Cowork เป็นการ์ดสีเข้มเพื่อเน้น เพราะ use case ทั้ง 18 อันในเดคนี้เป็นงานแบบมอบให้ทำจบ ซึ่งเป็นจังหวะของ Cowork

ข้อจำกัดที่ยังต้องบอกคือ "Claude ไม่เชื่อมกับระบบภายในบริษัทเอง ข้อมูลต้องแนบเข้าไป" อยู่ในสไลด์ 3 และ 5

### 2 สิ่งที่ผู้เข้าอบรมขอในแบบสอบถาม

โฟกัสของเดคนี้อยู่ที่ 2 เรื่องนี้เท่านั้น

1. **Prompt template พร้อมใช้ แยกตามสายงาน** — อยู่ในคลัง prompt (กด `L`) คัดลอกได้ทุกชุด
   ค้นหาและกรองตามสายงานได้ ทุก prompt ระบุไฟล์ที่ต้องแนบ และมี `[ตัวแปร]` ให้เติม
2. **คู่มือพร้อมใช้ ใช้ง่าย แยกตามสายงาน** — คู่มือ 4 ขั้นต่อสายงาน (กด `G`) บอกว่าสัปดาห์แรก
   ต้องตั้งอะไร เริ่มจากงานไหน และต้องตรวจอะไรก่อนส่ง พร้อมข้อควรระวังเฉพาะสายงาน

## แผนเวลา

**13–15 นาที (เต็ม)** — ตามลำดับสไลด์ทั้งหมด 18 สไลด์

**10 นาที (ถ้าเวลาถูกบีบ)** — ข้ามสไลด์ 3 (Claude คืออะไร) และสไลด์ 7 (prompt แย่ vs ดี)
พูดสไลด์สายงานสายละ 40 วินาที แล้วบอกให้ทุกคนไปอ่านสไลด์ที่ข้ามในเดคเองตอน workshop

สไลด์สายงาน (9–14) เป็นเนื้อหลัก และสไลด์ 4 (Chat vs Cowork) ไม่ควรข้าม เพราะเป็นตัวบอกว่า
ต้องเปิดตัวไหนตอนลงมือ — ถ้าต้องตัด ให้ตัดจากช่วงเปิดเรื่องและช่วงท้าย ไม่ใช่ตัดสายงาน

## แก้เนื้อหา

เนื้อหาทั้งหมดอยู่ที่ `content/deck.json` (แก้ไฟล์นี้เท่านั้น) แล้วรัน:

```bash
python3 scripts/build_deck_data.py
```

สคริปต์จะตรวจว่า track ครบ 6 สายงาน, แต่ละสายงานมี use case 3 รายการ, คู่มือ 4 ขั้น,
prompt 4–6 ชุดที่มี `[ตัวแปร]` ครบ แล้วจึงเขียน `data/deck-data.js` ที่ `index.html` โหลด

`data/deck-data.js` เป็นไฟล์ที่ถูกสร้างอัตโนมัติ — ห้ามแก้ตรงนั้น

## โครงไฟล์

```
index.html                  โครงหน้า + drawer ทั้งหมด
styles.css                  design system ตาม AP corporate deck
script.js                   renderer, keyboard control, font scaling, prompt/guide/library
content/deck.json           เนื้อหาที่แก้ได้ (single source of truth)
data/deck-data.js           สร้างจาก content/deck.json — ห้ามแก้มือ
scripts/build_deck_data.py  ตัว build + validator
assets/fonts/AP-*.woff2     ฟอนต์ AP แปลงจาก ~/Library/Fonts/AP-*.ttf
assets/img/                 โลโก้ AP (สว่าง/เข้ม) + favicon
references/                 ไฟล์อ้างอิงต้นทาง (รายชื่อผู้เข้าอบรม + deck Snowflake)
```

## หมายเหตุก่อนใช้จริง

- **ฟอนต์ AP และโลโก้ AP** รวมอยู่ใน repo เพื่อให้เดคแสดงผลตรงกับสไลด์องค์กร
  ทั้งสองอย่างไม่อยู่ภายใต้ MIT — ดูขอบเขตที่ [LICENSE](LICENSE) และ [NOTICE.md](NOTICE.md)
- **ตัวเลขเวลา before/after** ในสไลด์สายงานเป็นค่าประมาณ กำกับไว้บนสไลด์แล้วที่ footer
  ("* เวลาเป็นค่าประมาณ (estimate)…") ถ้าจะอ้างเป็นตัวเลขทางการ ต้องเก็บจริงจาก workshop ก่อน
- **สไลด์ 3 และ 4 บอกว่า Claude ไม่เชื่อมกับระบบภายในบริษัท** ซึ่งถูกกับการใช้งานผ่าน claude.ai
  ถ้าภายหลังมีการต่อ connector/MCP เข้าระบบภายใน ต้องแก้สองจุดนั้น
- **ไม่มีสไลด์รายชื่อผู้ติดต่อ** ตามที่สั่ง ข้อความที่ว่า IT จะรวม prompt ที่แต่ละทีมปรับจนใช้ได้จริง
  กลับเข้าคลัง ยังอยู่ในสไลด์ 17 (7 วันแรก ข้อสุดท้าย)
- **slide type `contacts` ยังอยู่ใน `script.js`** ถ้าจะเอาสไลด์ติดต่อกลับมา เพิ่ม object กลับใน
  `content/deck.json` แล้ว build ใหม่ ไม่ต้องแก้โค้ด
